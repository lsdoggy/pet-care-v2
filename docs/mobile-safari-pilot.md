# Проверка web-клиента для пилота

## HTTPS на VPS

После интеграции PR #32 соберите web командой `npm ci && npm run build`
из `apps/web`. Разместите содержимое `dist` в `infra/web-dist` на VPS.
В сервисе Caddy из `infra/compose.vps.yml` добавьте read-only mount
`./web-dist:/srv/petcare-web:ro`. В существующем HTTPS-блоке Caddy используйте:

```caddyfile
https://{$API_DOMAIN} {
    @backend path /api/* /files/*
    handle @backend {
        reverse_proxy backend:8080
    }
    handle {
        root * /srv/petcare-web
        try_files {path} /index.html
        file_server
    }
}
```

Задайте публичный DNS-адрес через `API_DOMAIN` в `infra/.env`.
Android APK и браузер используют один backend и одну БД. Для APK адрес API —
`https://<API_DOMAIN>` (клиент добавляет `/api/v1`). Web использует относительные пути
`/api/v1` и `/files`, поэтому запросы остаются на том же origin.
JWT передаётся через `Authorization: Bearer`. Дополнительные CORS-правила
и cookie для web не требуются.

Перед пилотом проверьте `/api/v1/health`, загрузку JS/CSS, обновление
внутренней страницы по прямому URL и открытие загруженного файла по HTTPS.

## Чек-лист

Используйте отдельную тестовую учётную запись и вымышленные данные.
Запишите модель устройства, версию ОС и браузера для каждого прогона.

- [ ] В Safari на iPhone проверьте портретную и альбомную ориентации. Дополнительно проверьте ширины 320, 375, 390 и 430 px в режиме адаптивного дизайна.
- [ ] Нет горизонтальной прокрутки. Верхняя панель, вкладки и кнопки формы доступны при раскрытой и свёрнутой панели браузера.
- [ ] Зарегистрируйтесь, войдите, обновите страницу, выйдите и войдите снова.
- [ ] Добавьте питомца, прикрепите JPEG или PNG из медиатеки, сохраните и убедитесь, что фото загружается после обновления страницы.
- [ ] Создайте ветеринарный визит и медицинскую запись. Проверьте выбор даты, сохранение и отображение в истории.
- [ ] Откройте форму, вызовите клавиатуру в нижнем поле, прокрутите к кнопке сохранения, закройте клавиатуру и завершите ввод.
- [ ] Создайте позицию корма, измените остаток, добавьте позицию в покупки и отметьте покупку с пополнением остатка.
- [ ] Повторите основные сценарии в Android Chrome и подтвердите, что тестовые данные видны в APK с той же учётной записью.

## Локальная проверка раскладки

В headless Chromium проверены страницы `/login` и `/register` при ширинах
320, 375, 390 и 430 px. На всех ширинах горизонтальной прокрутки нет,
вычисленный размер шрифта каждого поля ввода — 16 px. Проверка охватывает
отрисовку форм. Вход, создание аккаунта и поведение клавиатуры проверяются
отдельно по чек-листу на устройствах.

На тех же ширинах с тестовыми ответами API проверены главная, запасы и
покупки в Chromium и WebKitGTK 4.1, а профиль питомца — в Chromium.
Горизонтальной прокрутки нет. WebKitGTK также подтвердил раскладку входа
и регистрации. После исправления поле быстрого добавления покупки имеет
размер шрифта 16 px в обоих движках, а все девять полей формы товара —
16 px в Chromium. Проверки выполнены на Linux. Прогон на iOS и Android,
системная клавиатура, загрузка фото и работа с реальным API ещё не проверены.

После перевода формы товара на общий модальный компонент в Chromium
повторно проверены ширины 320, 375, 390 и 430 px при высоте окна 460 px.
Форма прокручивается до кнопки сохранения без горизонтальной прокрутки.
Фокус переходит в форму при открытии и возвращается к кнопке добавления
товара после закрытия клавишей Escape. Все девять полей имеют размер 16 px.
