# Android-приложение закрытой альфы

## Настройка подписанной сборки

Работайте из `apps/mobile`. Привяжите приложение к командному Expo-проекту
командой `npx eas-cli init`. Сохраните в конфигурации проекта его публичный EAS
project ID. Используйте один Expo-проект и один Android application ID
`com.lsdoggy.petcare` для всех обновлений альфы.

1. В Firebase добавьте Android-приложение `com.lsdoggy.petcare`. В EAS создайте
   файловую переменную `GOOGLE_SERVICES_JSON` с видимостью Secret для окружения
   `preview`. Загрузите туда клиентский файл `google-services.json`.
2. Включите Firebase Cloud Messaging API v1 и настройте сервисный аккаунт
   Firebase с правами для отправки FCM. Загрузите его ключ в **Expo → Credentials
   → Android → Service credentials → FCM V1 service account key**. Этот ключ
   хранится в Expo Credentials. Ссылки на настройку есть в
   [документации Expo по FCM v1](https://docs.expo.dev/push-notifications/fcm-credentials/).
3. Задайте переменную `EXPO_PUBLIC_API_URL` окружения `preview`. Укажите
   публичный HTTPS origin без пути и завершающего слеша. При выпуске EAS
   подписывает APK сохранённым Android keystore и увеличивает `versionCode`.
4. Для VPS включите `EXPO_PUSH_ENABLED=true`. Если проект требует авторизацию
   отправки через Expo, задайте `EXPO_PUSH_ACCESS_TOKEN` из защищённого
   хранилища. Транспорт API — Expo Push Service. Доступ к FCM настраивается в Expo.
   Серверу нужны исходящие HTTPS-запросы к `exp.host`.

```bash
npx eas-cli build --platform android --profile preview
```

## Установка и обновление

Раздавайте APK через закрытый канал поддержки. Запишите ревизию исходников,
ссылку на сборку в EAS, SHA-256 APK и номер версии. Участник открывает APK на
Android и подтверждает установку из этого источника. Для обновления участник
открывает более новую сборку поверх установленной. Для этого подпись и
application ID должны совпадать. После обновления откройте приложение и
проверьте вход и уведомления.

## Приёмка на физическом Android

Используйте вымышленные аккаунты и данные.

- Установите APK, войдите в первый аккаунт и разрешите уведомления. Проверьте
  создание канала «Pet Care» и регистрацию устройства в API.
- Запланируйте штатную задачу на ближайшее время. Проверьте доставку при
  свёрнутом приложении и закрытом интерфейсе. Коснитесь уведомления и
  убедитесь, что актуальная задача выделена в списке. Отдельно проверьте
  переход из уведомления о корме к запасам.
- Отклоните запрос разрешения на чистой установке. Проверьте вход и отсутствие
  доставки. Разрешите уведомления в настройках Android, затем перезапустите
  приложение и проверьте регистрацию.
- Выйдите из первого аккаунта онлайн. Проверьте отвязку устройства и доставку
  после входа во второй аккаунт. Повторите сценарий смены аккаунта после выхода
  без сети. Владелец токена меняется при следующей успешной регистрации.
- Установите обновление поверх исходного APK и повторите тест доставки.

Запишите модель устройства, версию Android, версию APK, ревизию API, время
запланированной задачи и наблюдаемый результат. Для диагностики проверьте
разрешение ОС, канал, настройку push пользователя, свежую регистрацию
устройства, состояние задачи и журнал backend. Успешный билет Expo означает,
что отправка поставлена в очередь. При ошибке `DeviceNotRegistered` из билета
или квитанции сервер отключает токен, если с момента отправки его не
зарегистрировали заново. Квитанции начинают проверяться через 15 минут.
Ошибки credentials и несовпадение Firebase sender ID требуют сверки проекта
Firebase, клиентской конфигурации и сервисного ключа.

Сборку и физическую приёмку должен выполнить владелец подключённых Expo,
Firebase и устройства. Сведения о фактическом прогоне внесите в [#59](https://github.com/lsdoggy/pet-care-v2/issues/59).
