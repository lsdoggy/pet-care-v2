# Восстановление доступа по email

На экране входа в web выберите «Восстановить доступ» и укажите email аккаунта.
В Android введите email на экране входа и нажмите «Запросить ссылку на указанный email».
Откройте письмо в браузере. Для действующего аккаунта форма предложит установить новый
пароль. Для деактивированного аккаунта подтвердите восстановление и войдите с прежним
паролем. Если прежний пароль забыт, снова запросите ссылку после восстановления аккаунта.

Если открыть другую ссылку в той же вкладке, форма начнёт новый сценарий.
При сбросе пароля его потребуется ввести заново.

Ссылка сброса действует 30 минут, ссылка активации — 24 часа. После истечения срока
можно запросить новую. Между успешными отправками для одного аккаунта выдерживается
минимум одна минута. Новая отправленная ссылка заменяет предыдущую. Ссылки активации,
выданные до миграции V20, действуют ещё 24 часа после неё. Сброс пароля завершает
ранее выданные сеансы.

## Настройка VPS

Заполните в закрытом `infra/.env`:

- `APP_ACCOUNT_RECOVERY_PAGE=https://<web-host>/restore-account`
- `APP_PASSWORD_RESET_PAGE=https://<web-host>/reset-password`
- `MAIL_HOST`, `MAIL_PORT` (по умолчанию 587), `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM`.

SMTP должен поддерживать аутентификацию и STARTTLS. Проверьте, что публичный web
открывает оба маршрута напрямую и проксирует `/api/` к backend. Токен передаётся в
фрагменте URL и отправляется в теле POST после подтверждения. Не включайте
логирование тел запросов для auth и отладку SMTP на production.

При отсутствии письма проверьте настройки домена отправителя и папку спама.
На backend проверьте сообщения `SMTP send failed` и `SMTP not configured`.
При ошибке SMTP деактивация возвращает 503 и оставляет аккаунт активным.
Запрос ссылки для существующего и неизвестного email возвращает одинаковый 204.
При заполнении очереди запросов API возвращает 503. Очередь находится в памяти
backend, поэтому после перезапуска может понадобиться повторный запрос.

## API

- `POST /api/v1/auth/request-access-link` принимает `{ "email": "..." }` и ставит
  запрос в очередь.
- `POST /api/v1/auth/reset-password` принимает `{ "token": "...", "password": "..." }`
  и возвращает 204 после смены пароля.
- `POST /api/v1/auth/restore-account` принимает `{ "token": "..." }` и возвращает
  204 после активации.
- Для истёкшей, уже погашенной или предназначенной для другого действия ссылки
  endpoint подтверждения возвращает 400.

## Приёмка

На физических Android и iPhone с фиктивным аккаунтом проверьте доставку обоих
писем, открытие публичной страницы из почтового приложения, одноразовость ссылки
и вход после подтверждения. В отчёте укажите ревизию, устройство и время проверки.
Не прикладывайте содержимое письма, токен или снимок адресной строки.
