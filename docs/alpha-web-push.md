# Web Push на iPhone

## Развёртывание

Опубликуйте web и `/api/v1` на одном HTTPS origin. Проверьте, что
`/manifest.webmanifest` и `/push-worker.js` отдаются отдельными файлами
с корректными типами содержимого. Service worker отвечает за уведомления.
Авторизованные страницы и API-ответы он не кэширует.

Для каждого окружения подготовьте постоянную пару VAPID P-256. Публичный ключ
кодируется как несжатая точка кривой из 65 байт, приватный как 32-байтовый скаляр.
Оба ключа передаются в Base64URL без дополнения. Подойдут, например, ключи из
команды `web-push generate-vapid-keys` CLI проекта web-push. Запускайте
генерацию в доверенном окружении. Приватный ключ храните вместе с секретами
окружения. При смене пары пользователи должны отключить и включить Web Push заново.

| Переменная backend | Значение |
| --- | --- |
| `WEB_PUSH_VAPID_PUBLIC_KEY` | Публичный VAPID-ключ, доступный клиенту |
| `WEB_PUSH_VAPID_PRIVATE_KEY` | Приватный VAPID-ключ |
| `WEB_PUSH_VAPID_SUBJECT` | Контакт оператора, например `mailto:push@example.org` |

Пустые значения отключают транспорт. При неполной конфигурации backend завершает
запуск с ошибкой. Для исходящего трафика разрешите HTTPS-доступ к
`*.push.apple.com`. Транспорт отправляет уведомления без payload. Service worker
показывает нейтральный текст без имени питомца и деталей задачи и открывает главную
страницу Pet Care, где видны напоминания.
[Документация Apple по Web Push](https://developer.apple.com/documentation/usernotifications/sending-web-push-notifications-in-web-apps-and-browsers).

## API подписок

Endpoint подписки используется как секрет. Обращения к API требуют JWT
владельца. `GET /api/v1/web-push/config` возвращает публичный ключ
`publicKey` или пустую строку при выключенном Web Push.
`PUT /api/v1/web-push/subscription` привязывает Apple endpoint к аккаунту.
`POST /api/v1/web-push/status` возвращает `subscribed` для текущего аккаунта.
`DELETE /api/v1/web-push/subscription` удаляет только привязку текущего владельца.
Эти три запроса принимают JSON с полем `endpoint`. При выходе приложение
запрашивает удаление на сервере и отмену подписки в браузере.

## Проверка на iPhone

1. На iOS 16.4 или новее откройте HTTPS-адрес Pet Care в Safari. Через меню
   «Поделиться» добавьте приложение на экран «Домой». Откройте его с иконки.
2. Войдите под тестовым аккаунтом. В профиле включите общую настройку
   push-уведомлений, нажмите «Включить Web Push на этом устройстве» и разрешите
   уведомления в системном диалоге.
3. На вымышленных данных создайте задачу с близким сроком. Закройте приложение
   и заблокируйте экран. Дождитесь уведомления, проверьте нейтральный текст,
   нажмите на него и проверьте открытие главной страницы Pet Care.
4. Выйдите из аккаунта. Создайте для него новое напоминание с другого устройства
   и убедитесь, что Web Push больше не приходит. Войдите во второй аккаунт и
   повторите включение и доставку с отдельной подпиской.
5. Повторите с запретом системного разрешения и с отключённым общим переключателем.
   При необходимости восстановите разрешение в системных настройках.
6. Запишите модель и версию iOS, адрес стенда, ревизию приложения и результаты
   в чек-лист приёмки.

При отсутствии доставки проверьте запуск с VAPID, установку на экран «Домой»,
разрешение iOS, настройку канала и расписание задачи. Backend логирует HTTP-код
ошибки push-сервиса. Ответы 404 и 410 удаляют устаревшие подписки. При их
получении снова откройте профиль и включите Web Push.

Проверка на физическом iPhone и доставка через Apple в целевом окружении
ожидают приёмки.
