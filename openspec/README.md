# OpenSpec: baseline текущего приложения

Этот каталог фиксирует **реализованное поведение**, исследованное по исходному коду и существующим backend-тестам. Это не roadmap, не предложение реализовать перечисленные функции заново и не отчёт об успешном прогоне приложения.

Baseline подготовлен 2026-11-12 для исходников на commit `d85f61eb844fbd097b0929b9610cde5cd32278fa`. На момент исследования tracked-изменений приложения в рабочем дереве не было.

## Как читать baseline

- `SHALL`/`MUST` в этих документах фиксируют текущий контракт, а не новую работу на реализацию.
- Основной источник истины при создании baseline — код; README и комментарии могут описывать прежние спринты и расходиться с реализацией.
- `Implementation references`/другие ссылки на источники помогают перепроверять поведение. Сценарии — документированные примеры, не автоматически сгенерированные исполняемые тесты.
- Разделы ограничений и примечания не следует принимать за желаемые исправления. Для изменения поведения создаётся отдельный change.
- Не заявляется исчерпывающее описание всех внутренних полей БД, CSS-токенов и каждой framework-ошибки. Доменный контракт и пользовательские сценарии отделены от деталей развёртывания.

## Известные отличия клиентов

| Поведение | Web | Mobile |
|---|---|---|
| Просрочка в dashboard | Сравнение срока с текущим временем | Сравнение с началом текущего дня |
| Визиты в блоке внимания | Один ближайший за 7 суток | Визиты за 14 суток, с общим лимитом блока 6 |
| Ближайшие события | До 6, задачи могут быть просроченными | До 8, только будущие задачи/визиты |
| Быстрая покупка на главной | Создаёт продукт с нулевым остатком для подсказок | Создаёт custom-позицию списка покупок |
| Создание/удаление продуктов | Доступно в запасах | В текущем Stock-экране отсутствует |
| Ошибки источников dashboard | Частичные данные; ошибка питомцев блокирует dashboard | Сбой любого источника показывает общую ошибку |

Дополнительно: URL фото/вложений публичны; токены клиентов хранятся в localStorage/AsyncStorage; NotificationBell существует, но не подключён в web AppShell; быстрые ссылки вкладок mobile имеют ограничение синхронизации стека, указанное в mobile-client.

В уведомлениях обнаружено статическое несоответствие: JPA `EnumType.STRING` сохраняет uppercase-имена enum, а миграция V6 ограничивает `type` и `channel_status` lowercase-значениями. Это потенциально блокирует сохранение уведомлений в мигрированной БД; успешная end-to-end доставка не подтверждена. FCM-отправитель является заглушкой. Детали и границы реализованного алгоритма описаны в [notifications](specs/notifications/spec.md).

## Проверка

Из корня репозитория приложения:

```powershell
openspec.cmd list --specs
openspec.cmd validate --specs --strict --no-interactive
```

На системах без ограничения PowerShell launcher можно использовать `openspec` вместо `openspec.cmd`.

В рамках документирования проверяется формат спецификаций. Backend-тесты и клиентские сборки сами по себе не считаются выполненными: их запуск должен подтверждаться отдельным результатом.

## Дальнейшие изменения

1. Исследовать задачу: `/openspec-explore`.
2. Создать предложение: `/openspec-propose "описание изменения"`.
3. Согласовать proposal, delta specs, design и tasks.
4. Выполнить изменение: `/openspec-apply-change`.
5. После проверки архивировать: `/openspec-archive-change`.

Baseline записан прямо в `specs/`: искусственный change с фиктивными задачами реализации не создавался. При архивировании будущих изменений delta-требования должны обновлять эти спецификации.
